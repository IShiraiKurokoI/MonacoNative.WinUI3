# Keyboard shortcuts

`MonacoEditor` provides two built-in Windows keybinding profiles. The default is
`EditorShortcutScheme.VSCode`; applications may switch to
`EditorShortcutScheme.VisualStudio` without recreating the control.

```csharp
Editor.ShortcutScheme = EditorShortcutScheme.VisualStudio;
Editor.ShortcutScheme = EditorShortcutScheme.VSCode;
```

The editor exposes WinUI-level overrides for the registered command IDs. An
override replaces **all** bindings for the command in both profiles; it is not
an extra binding merged with the active profile. Overrides remain in effect
when switching profiles. Pass an empty array to disable the keyboard shortcut
without disabling the command, or `null` to restore the profile binding.
Invalid key chords are rejected and the previous bindings are restored.

```csharp
// Replace the document formatting keybinding.
Editor.SetShortcutOverride("editor.action.formatDocument",
    new EditorShortcutBinding("Ctrl+Alt+F"));

// An additional conditional chord can be passed in the same call.
Editor.SetShortcutOverride("editor.action.formatDocument",
    new EditorShortcutBinding("Ctrl+Alt+F", 1000, "editorTextFocus && !editorReadonly"),
    new EditorShortcutBinding("Ctrl+K Ctrl+D", 900));

// Unbind it, while keeping its programmatic and context menu actions available.
Editor.SetShortcutOverride("editor.action.formatDocument", []);

// Restore the chosen profile's mapping.
Editor.SetShortcutOverride("editor.action.formatDocument", null);

// Execute a registered command from the host application.
await Editor.ExecuteCommandAsync("editor.action.formatDocument");
```

| Action | VS Code | Visual Studio |
| --- | --- | --- |
| Format document | `Shift+Alt+F` | `Ctrl+K Ctrl+D` |
| Format selection | `Ctrl+K Ctrl+F` | `Ctrl+K Ctrl+F` |
| Toggle line comment | `Ctrl+/` | Unbound; use comment/uncomment chords |
| Comment selection | `Ctrl+K Ctrl+C` | `Ctrl+K Ctrl+C` |
| Uncomment selection | `Ctrl+K Ctrl+U` | `Ctrl+K Ctrl+U` |
| Toggle word wrap | `Alt+Z` | `Ctrl+E Ctrl+W` |
| Delete current line | `Ctrl+Shift+K` | `Ctrl+Shift+L` |
| Parameter info | `Ctrl+Shift+Space` | `Ctrl+Shift+Space` |
| Previous/next overload | `Alt+Up/Down` | `Up/Down` while parameter info is visible |

In the Visual Studio profile, plain Up/Down switches overloads only while
parameter info is visible and the completion list is closed. Outside that context,
these keys move the caret normally. In the VS Code profile, overload navigation
continues to use Alt+Up/Down.

Other navigation, editing and IntelliSense commands retain the editor's common
bindings in both profiles. The Visual Studio profile covers the implemented
editing commands, not every command installed by the full Visual Studio IDE.

Shortcut spelling follows the WinUI keybinding resolver. For example,
`Ctrl+OemQuestion` is the physical `/` key, while `Ctrl+OemPeriod` is `Ctrl+.`.
Shortcut overrides participate in the same context and read-only checks as
built-in bindings. The native TSF/IME key handler is given first refusal;
shortcuts do not consume keys during an active composition.

The sample application's **Keyboard shortcuts** selector can switch profiles.
An embedding application may configure overrides during initialization or
when updating its own command settings.

Context-menu accelerator labels are generated by the editor's command service
from the current profile or host override. Hosts should use
`SetShortcutOverride` instead of building replacement menu labels themselves.
